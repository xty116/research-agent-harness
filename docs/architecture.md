# 架构、上下文与记忆

## 为什么这样划分

固定时刻和固定目标不要求固定研究路径。系统使用一个模型控制的动作循环，外层由确定性 Harness 管理证据、资源和恢复。它不是把每个工具排成固定 DAG，也不把可验证性委托给一个模型自评分。

`Harness` 负责生命周期；`ToolExecutor` 提供有限动作接口；`ContextBuilder` 决定本次模型看到的材料；`Store` 集中管理原子事务、执行租约和预算。来源适配器、模型和本地检索可以替换，领域对象保持稳定。当前不依赖 LangGraph，避免同时维护两套检查点语义。

## 状态与决策

`ResearchTask` 保存目标、方向、实体、优先级、缺口、原文 ID、完成条件和重试时间。`Decision` 每次包含一个工具调用以及可选的新问题、优先级调整及简短理由。最多 8 个任务，初始建议最多 4 个；默认最多 24 步、600 秒。

扫描是有界的基线覆盖，研究循环是模型选择。每次重新构建上下文，模型根据当前证据、缺口、业务权重和剩余额度做决定。任务的研究优先级 1–5 与最终业务建议 P0/P1/P2 分开。

## 上下文工程

每次调用都重建上下文，不无限追加聊天记录：

1. 保护固定任务、外部文本处理规则、预算、任务完成条件和断言身份。
2. 候选目录最多 12 条，按四方向轮转选择，避免高产信源挤掉其他方向。完整材料留在 SQLite，目录不是数据库本身。
3. Skill 元数据始终可见，正文通过 `load_skill` 加载；正文和按需参考资料有独立额度，可卸载不用的 skill。
4. 原文按问题挑选片段，长段落先切块，用词项稀缺度排序。模型可用 `find_in_document` 定位数字/短语，也可分页读取，解决相关性摘要遗漏表格的问题。
5. 最近观察完整保留，较早观察只保留动作、结果及证据 ID。历史材料和历史结论单独标记时间，不当成当天新事实。
6. 先裁剪历史召回、较早活动、原文片段、观察和待办，再压缩断言的展示字段、缩小候选目录；原始状态与证据不删除。
7. 报告草稿在 Critic 上下文裁剪之前加入。每次保存上下文的保守大小、加载 skill 和证据条数，便于排查溢出。

配置中 `max_*_tokens` 为保守 UTF-8 字节上界，而非精确 tokenizer 计数。实际收费 tokens 来自供应商 usage。系统和 JSON Schema 留出额外空间；保护状态超限时失败并留下部分完成报告，不静默丢掉任务约束。

## 分层记忆

| 层 | 保存位置 | 生命周期与读取规则 |
| --- | --- | --- |
| 工作记忆 | `runs.checkpoint` | 当前计划、最近观察、证据 ID 和已加载 skills；每次动作后保存 |
| 情节记忆 | `events` | 计划、决策、观察、上下文统计、模型用量和完成事件；追加记录 |
| 证据记忆 | `documents`、`run_documents`、FTS、vectors | URL 与正文内容共同确定版本；同 URL 变更正文产生新版本 |
| 结论记忆 | `claims` | 同实体和同断言聚合修订；保留旧记录，默认召回最新修订 |
| 任务记忆 | `tasks` | 未解决问题延期，默认 24 小时后重试；实体出现新线索可提前重新进入规划上下文 |
| 程序记忆 | 版本化 `skills/` | 人维护研究方法和检查规则；模型只选择和读取，不自行改写或安装 |

FTS 词项召回与本地 Qwen3 向量召回通过 reciprocal-rank fusion 合并，默认回看 30 天。向量查询按 Qwen 指令格式构造，并在进程内缓存。模型不可用时转为 FTS，并明确显示状态；不会因此把整个日报判成功。向量模型更换时按模型标识重新索引。

记忆不是“已验证事实”的同义词：每条有来源、版本、抓取时间及用途。时间敏感结论必须重新取证。新抓到的同一份内容仍保留原始证据版本，其本次被读取的关系在 `run_documents` 记录。

人工可通过 `archive-task --reason` 将不再适用的问题归档。归档与核验完成是不同状态，不删除任务或历史，且追加管理事件。模型没有归档工具，不能靠隐藏问题来通过质量门禁。联调产生的纯工程修复事项已经按此方式归档，真实研究缺口继续保留。

目前没有独立的实体关系图、自动知识合并或模型自动修改长期规则。实体用于问题去重、召回和断言修订；这些边界避免把普通存储包装成未经实现的知识图谱。

## 强弱调用与资源

非思考：初始分类、原子断言评估。思考：规划、每一步控制、冲突裁决、综合和五维 Critic。本地逻辑：日期过滤、内容版本去重、FTS、向量计算、引用校验、预算、检查点和页面渲染。

调用前以保守输入上界和最大输出计算额度并写入 SQLite。成功后按 usage 结算；明确未接受的 4xx 释放额度；超时、网络中断、未知 5xx 保留预占。研究不能消耗报告预留。费用按请求发生的本地日期计算，跨午夜重试也不绕过每日上限。Tavily 基础搜索 credits 单独计数。

思考模式使用独立输出上限，防止思考内容挤掉最终 JSON。结构化输出错误在有限次数内重试，并给出不含原始输入的字段校验提示。原始思维链不写入记忆或日志。API 返回的底层模型名也保留，避免旧别名变化后误报模型身份。

## 证据与质量门禁

`ClaimAssessment` 输出 support / contradict / unverified，并引用已观察到的文档 ID 与原文。程序校验引用属于所选证据、引文真实存在、立场与裁决匹配；搜索摘要单独不能形成已核验结论。冲突由思考调用再次裁决。

事实性发现必须引用当前运行的断言；未证实结论只能以推断/未知展示；P0/P1 建议必须有已核验依据。五维 Critic 检查事实、完整性、引用、时效与可操作性。最多一次补查；缺失信源、未解决任务、失败评审或引用校验错误都会使报告为 `partial`。

这些是可靠性约束，不是语义正确性的数学保证。引用存在不代表它足以推出结论，Critic 也可能犯错。报告保留原文链接、引文、局限和轨迹，支持人工复核。

## 恢复与安全边界

单实例执行租约与心跳防止重叠研究，SQLite WAL + 原子事务保存状态。每日调度有唯一键。调用意图在外部动作前落盘，动作结果之后再存检查点。进程崩溃在这两者之间时，外部只读调用可能重做，属于 **至少一次** 执行，不能承诺恰好一次；未知计费预占仍保留。

中断后恢复原运行的预算和开始时间，不重置总时限。超过时限会降为部分交付，把未完成问题延期。报告按运行 ID 原子写入，不覆盖同日其他报告。

外部网页与记忆都视为数据，不能提升为系统指令。模型只能调用注册工具，不能执行任意 Python/Shell。HTTP 校验公共地址、固定解析 IP、逐跳验证重定向和限制响应大小；浏览器无登录态，网络也经过同一取证层，只允许读请求。数据样本工具只读取 `data/samples` 中有界本地样本，并返回汇总统计。

## 阅读模型与报告归档

执行用 `RunState` 保持恢复语义；交付用 `report_model.report_bundle` 构建标准化 DTO，不改写历史。`reporting` 原子生成 Markdown、原状态 JSON、标准报告 JSON 和内嵌样式 HTML；`rendering` 统一 Jinja 自动转义。FastAPI 通过同一 DTO 展示实时快照与终态报告，不依赖磁盘文件存在，补报不会调用模型。

完整组件、调用时序、记忆关系、数据表与部署图见 [项目组织结构](structure.md)，所有页面和导出契约见 [报告与接口](reports.md)。
